# tianbao 3D 家庭场景设计

状态：**仅设计，未接入 3D 渲染。** 当前网页中的 `3D` 页是概念与导入流程的设计预览，不会伪装成已经可用的 3D 场景。

## 1. 目标与边界

3D 模式要解决的问题不是“做一个炫技的 3D 主页”，而是：

> 把用户真实的家的空间，变成一个 tianbao 能理解、能行走、能陪伴的 3D 场景。

第一版应满足：

- 能导入一套户型（客厅、卧室、厨房、走廊等）。
- 比例、朝向、门窗位置大致正确。
- tianbao 能在里面行走、避障、被叫到某个房间。
- 手机和电脑浏览器都能较流畅运行。
- 导入方式尽量通用，不绑定某一种扫描设备或某一家模型服务。

第一版**不追求**：

- 照片级真实渲染。
- 全屋高精度扫描。
- 完整物理模拟。
- 多人同时在线。

## 2. 推荐路线：户型图 → 语义房间 → 体块/家具 → 导航

### 为什么不是“先做真实扫描”

真实扫描（LiDAR、RoomPlan、Polycam、Gaussian Splatting）效果很吸引人，但作为第一版依赖会有明显问题：

1. 设备门槛高：很多用户没有 LiDAR 手机。
2. 数据重：全屋 scan/splat 文件大，手机加载和渲染压力大。
3. 清洗成本高：扫描噪声、重复面、家具遮挡需要人工处理。
4. 不够通用：不同扫描工具的输出格式和坐标规范差异很大。
5. 迭代慢：改一个房间或换一套户型，就要重新扫描。

### 更稳的路线

**用户型图做“骨架”，再用可选的真实扫描做“皮肤”。**

```text
户型图/手绘平面图
      ↓
标定比例、朝向、墙体
      ↓
语义房间（客厅/卧室/厨房/卫生间/走廊）
      ↓
门窗、家具 footprint、可走区域
      ↓
体块/风格化 3D 场景（第一版）
      ↓
可选：真实扫描、照片纹理、splat 增强（后续）
```

这条路线简单、通用、可控，也最适合先把“tianbao 住进家里”这个核心体验跑通。

## 3. 导入流程（第一版建议 5 步）

1. **上传平面图**
   - 支持 PNG / JPG / SVG / PDF 第一页。
   - 也允许“从空白开始画”。
2. **标定比例与朝向**
   - 用户点两个点，输入真实距离（例如门宽 0.9m）。
   - 指定北向/入口方向。
3. **框选房间**
   - 矩形或自由多边形。
   - 给房间打标签：客厅、卧室、厨房、餐厅、走廊、卫生间、阳台。
4. **标记门窗与可走区域**
   - 门/开口决定房间连通图。
   - 窗决定采光和视野。
   - 可走区域默认是房间内部减去家具 footprint。
5. **体块预览与家具**
   - 先生成白模/低多边形体块，让用户确认比例。
   - 再从一个小型家具库放置沙发、床、桌子、柜子等。
   - 家具只记录位置、旋转、尺寸和类型，不要求高模。

导入结果应能保存为一份可复用的 `floorplan.json`，以后换设备、换渲染器都不需要重做。

## 4. 通用数据模型（建议）

```json
{
  "version": 1,
  "unit": "meter",
  "north": 0,
  "origin": [0, 0, 0],
  "rooms": [
    {
      "id": "living",
      "name": "客厅",
      "type": "living",
      "polygon": [[0, 0], [4.2, 0], [4.2, 3.6], [0, 3.6]],
      "floor": 0,
      "walls": [
        {"from": [0, 0], "to": [4.2, 0], "height": 2.8, "openings": [
          {"type": "door", "at": 1.2, "width": 0.9, "height": 2.1},
          {"type": "window", "at": 2.8, "width": 1.4, "height": 1.2, "sill": 0.9}
        ]}
      ]
    }
  ],
  "furniture": [
    {"type": "sofa", "room": "living", "position": [3.2, 2.4], "rotation": 90, "size": [1.8, 0.8, 0.8]}
  ],
  "walkable": [
    {"room": "living", "polygon": [[0.2, 0.2], [4.0, 0.2], [4.0, 3.4], [0.2, 3.4]]}
  ],
  "links": [
    {"from": "living", "to": "hall", "door": [4.2, 1.2]}
  ]
}
```

设计原则：

- **房间是语义单位**，不是一堆三角面。tianbao 需要知道“这是卧室”，而不只是“这里有墙”。
- **门窗是连通关系**，后续寻路、被叫到房间、避免撞墙都依赖它。
- **家具 footprint 优先于模型**。先保证碰撞和可走区域，再追求外观。
- **单位统一为米**，坐标统一为房间平面坐标 + 高度；渲染器只负责转换。

## 5. 技术选型建议

### 渲染

- **Three.js**（WebGL2）+ glTF/GLB 资产。
- 第一版用 **风格化体块 + 少量低模家具**，不做照片级材质。
- 光照优先使用 **烘焙/环境光 + 少量实时灯**；手机上避免大量实时阴影。
- 纹理使用压缩格式（KTX2/Basis），模型做 LOD；目标中端手机 30fps 左右。
- 相机提供两种模式：
  1. **Dollhouse / 俯视**：导入与编辑时看全局。
  2. **第三人称跟随**：tianbao 在家里行走时使用。

### 导航

- 用房间可走区域生成 **navmesh** 或网格 A*。
- tianbao 用胶囊体碰撞，避免穿墙、卡家具。
- 支持：
  - 点击某处 → 走过去。
  - “去客厅” → 通过房间连通图规划路径。
  - 被叫到身边 → 找到用户所在房间/位置。
- 第一版不需要复杂动作捕捉；走路、转身、坐下、待机即可。

### 真实扫描作为增强

后续可以支持：

- iPhone LiDAR / RoomPlan 导出的简化户型。
- GLB/OBJ 房间扫描。
- Gaussian Splatting 作为“背景皮肤”，但仍保留语义房间和导航网格。

关键点：**扫描结果只提供视觉和几何，不替代语义房间与导航数据。**

## 6. 手机性能预算（建议）

- 同屏三角面：< 150k（中端手机）。
- draw call：< 120。
- 实时阴影：最多 1 个方向光，或关闭。
- 纹理：单张不超过 1024/2048，KTX2 压缩。
- 粒子/光效：少量，可开关。
- 首次加载：体块场景目标 < 5MB；真实扫描单房间 < 20MB。
- 低端设备提供“体块模式”降级。

## 7. tianbao 在 3D 里的存在感

- 3D tianbao 不必复刻 2D SVG 的每个细节，但要保留：
  - 圆角头、深色屏幕、青色脸、天线灯、柔软身体。
  - 情绪状态映射到眼睛、嘴、头部动作。
- 行走/跳跃/坐下/待机动画用简单的骨骼或分组动画即可。
- 房间感知：
  - 知道自己在哪个房间。
  - 被叫到名字时转向声源/用户位置。
  - 能表达“我在这间屋子里”的空间感。
- 情绪系统继续由 Flask 作为权威来源，3D 只是另一个视图。

### 3D 摸头交互（设计）

- 用射线/包围盒命中 tianbao 的头部，而不是整只角色。
- 按住时间映射到与 2D/2.5D 相同的三档：轻摸、普通、亲昵；释放时只提交一次 `/api/touch`。
- 反馈：眯眼/闭眼、头轻微靠近手、爱心/粒子、可选的触觉振动；结束后根据最新后端情绪恢复。
- 移动端要避免长按触发浏览器菜单，并支持触摸取消/失焦复位。
- 当前 3D 页的“摸摸 3D tianbao”是这条交互的设计预演，使用同一套触摸状态机与真实 API；真正的 3D 射线命中会在 Phase 2 随 3D 场景一起接入。

## 8. 隐私与数据

- 户型图、房屋扫描默认**只存在本地浏览器/本地服务**。
- 上传到云端必须明确提示并获得用户同意。
- 导出文件由用户自己保管；服务端不长期保存家庭空间数据。
- 真实扫描文件可能包含家庭成员和私人物品，默认不做公开分享。

## 9. 分阶段落地

### Phase 1：导入与白模（推荐先做）

- 上传户型图、两点标定、矩形/多边形房间。
- 房间标签、门窗、简单家具 footprint。
- 俯视/dollhouse 预览。
- 导出/导入 `floorplan.json`。

### Phase 2：tianbao 进入场景

- 3D tianbao 模型与基础动画。
- navmesh、点击移动、房间连通、简单避障。
- 情绪/说话/倾听在 3D 中的映射。

### Phase 3：真实感增强

- 真实扫描/GLB/splat 导入。
- 更好的材质、光照、家具库。
- 手机性能降级策略与加载优化。

## 10. 需要确认的问题（反馈）

1. 第一版更想要**风格化体块**，还是必须接近真实照片？
2. 用户主要是自己导入，还是你预先替他们导入？
3. 户型图来源：开发商平面图、手绘、还是手机扫描？这决定标定和编辑的复杂度。
4. 是否需要多楼层/楼梯？
5. 家具库希望有多大？先做 10 个通用类型，还是绑定某一种风格？
6. tianbao 在 3D 里更需要“可爱陪伴感”，还是“真实空间导航感”？
7. 真实扫描是否作为第一版功能，还是后续增强？
8. 目标最低手机型号和系统版本是什么？

## 11. 结论

当前最稳的产品路线不是“先做全屋 3D 扫描”，而是：

> **户型图 → 语义房间 → 体块/家具 → 可走区域 → tianbao 导航 → 可选真实扫描增强。**

它简单、通用、可迭代，也能让 2.5D 小屋和未来的 3D 家共享同一套“房间/可走区域”思路。当前网页的 2.5D 小屋就是这个方向的轻量预演。
